# 実利用が拡大する前に構文の破壊的変更を進める

malgoの唯一の実利用先であるnix-config（メンテナ自身が管理するdogfooding用途）は、今後より広い場面での利用を目指している。#436のような構文の破壊的変更は、利用先が増えるほど移行コストが跳ね上がる。

コア構文糖の再設計（[0001](./0001-core-syntax-sugar-over-macros.md)）に伴う破壊的変更は、利用が自分の管理下にある今のうちに進める。利用が広がった後で安定版を切ってから変更する、という段階を踏まない。

## Consequences

構文の後方互換性を保つ調整コストは、今後利用が広がるほど大きくなるため、コア構文の再設計は先延ばしにしない。
